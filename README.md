# KINS 일일 언론동향 검색

한국원자력안전기술원(KINS) 일일 언론동향 업무를 자동화하는 내부용 웹 애플리케이션입니다.

사용자는 **검색 시작 날짜와 시간만 입력**하면, `검색 시작 시각 ~ 뉴스 검색 버튼을 누른 현재 시각(Asia/Seoul)` 범위에서
고정된 28개 키워드로 네이버 뉴스를 검색하고, 다음 작업을 자동으로 수행합니다.

1. 키워드별 네이버 뉴스 검색 (최신순, 페이지 순차 조회)
2. 최초 게시 시각 기준 기간 필터
3. 기사 원문 확인 (게시 시각·언론사·본문)
4. 무관 기사 제거 / 동명이인 제거
5. 중복 기사 제거 (같은 기사 병합 + 같은 사건 유사 보도 묶기)
6. 6개 주제 분류 + 중요도 정렬
7. 주제별 보기 / 키워드별 보기 / 전체 기사 / 제외 기사(검토용)
8. CSV · Excel · 보고용 텍스트 다운로드

> **원칙**: 존재하지 않는 기사·제목·언론사·URL을 만들지 않으며, 게시 시각을 추정하지 않고, 검색 범위 밖 기사나
> 무관한 기사로 건수를 채우지 않습니다. 제목은 원문 그대로(HTML 태그·중복 공백만 제거) 표시합니다.
> 결과가 없으면 `확인된 기사 없음 (0건)`으로 표시합니다.

## 2. 환경변수 설정

`.env.example`을 `.env`로 복사한 뒤 값을 채웁니다. **`.env`는 Git에 올라가지 않습니다(.gitignore).**

```bash
copy .env.example .env      # Windows
cp .env.example .env        # macOS / Linux
```

| 변수 | 필수 | 설명 |
|---|---|---|
| `NAVER_CLIENT_ID` | 필수 | 네이버 검색 API Client ID |
| `NAVER_CLIENT_SECRET` | 필수 | 네이버 검색 API Client Secret |
| `OPENAI_API_KEY` | 선택 | LLM 보조 판단용 API 키 |
| `OPENAI_MODEL` | 선택 | 사용할 모델명 (코드에 고정하지 않음 — 키와 함께 지정해야 LLM 사용) |
| `OPENAI_BASE_URL` | 선택 | OpenAI 호환 게이트웨이 주소 (기본 `https://api.openai.com/v1`) |
| `HTTP_TIMEOUT` 등 | 선택 | 동작 조정값 (`.env.example` 참고) |

### 네이버 검색 API 발급 방법
1. <https://developers.naver.com> 로그인 → **Application → 애플리케이션 등록**
2. 사용 API에서 **검색** 선택, 환경은 `WEB 설정`(URL은 `http://localhost` 등 아무 값)
3. 등록 후 표시되는 **Client ID / Client Secret**을 `.env`에 입력
4. 일일 호출 한도: 25,000회 (1회 검색 시 키워드 28개 × 최대 10페이지 = 최대 280회)

### (선택) LLM 보조 판단
`OPENAI_API_KEY`와 `OPENAI_MODEL`을 **모두** 설정하면 관련성·제외 대상·동명이인·주제·같은 사건 여부·중요도 판단에
LLM을 함께 사용합니다. 미설정이거나 오류가 나면 **규칙 기반 판단으로 자동 전환**되며 앱은 중단되지 않습니다.
화면의 `고급 옵션`에서 사용 여부를 끌 수 있습니다.

## 3. 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

브라우저에서 <http://localhost:8501> 접속. 동료와 공유하려면 같은 망에서 `http://<PC IP>:8501`로 접속합니다.
(포트 변경: `streamlit run app.py --server.port 8600`)

### 사용 방법
1. **검색 시작 날짜 / 시간** 입력 (기본값: 직전 영업일 16:00, 화면에서 자유롭게 변경 가능)
2. **뉴스 검색** 클릭 → 그 순간의 KST 시각이 검색 종료 시각이 됩니다.
3. 진행 상황(`[ 3 / 28 ] KINS 검색 중`, 기사 검색 → 상세 확인 → 기사 선별 → 중복 제거 → 주제 분류)을 확인
4. 결과 탭 전환: **주제별 보기 / 키워드별 보기 / 전체 기사 / 제외 기사(검토용)**
5. 필터(주제·검색 키워드·언론사·제목 검색)는 이미 수집된 결과에서만 동작합니다(API 재호출 없음).
6. CSV / Excel / 보고용 텍스트 다운로드

## 5. 검색 로직

- **28개 키워드만 각각 독립 검색**합니다 (`src/config.py`의 `NEWS_KEYWORDS`, 순서 고정). 연관어·동의어를 추가 검색하지 않습니다.
- 네이버 검색 API `sort=date`(최신순), `display=100`, `start=1, 101, …, 901` 순차 조회 (키워드당 최대 1,000건 — API 한도)
- **조기 중단**: 한 페이지의 가장 오래된 기사가 검색 시작 시각보다 이전이면 다음 페이지를 요청하지 않습니다.
- API 한도(1,000건)에 걸려 기간 초반 기사가 누락될 수 있으면 화면의 `확인 필요 알림`에 표시합니다.
- 모든 외부 요청에 timeout(기본 10초)과 exponential backoff 재시도를 적용합니다. 한 키워드/한 기사 실패는 전체 검색을 멈추지 않습니다.

### 시간 처리 (가장 중요)
- 모든 시각은 timezone-aware `Asia/Seoul`로 통일하여 `start <= 최초 게시 시각 <= 검색 버튼 클릭 시각`(경계 포함)만 남깁니다.
- 최초 게시 시각 우선순위: **① 기사 원문 페이지의 최초 입력 시각 → ② 네이버 뉴스 페이지의 입력 시각 → ③ 검색 API `pubDate`**
- 수정 시각은 게시 시각으로 쓰지 않습니다(수정 시각만 범위 안이면 제외).
- 신뢰할 수 없는 값은 버리고 다음 순위로 넘어갑니다: 미래 시각, API 시각보다 6시간 이상 늦은 값(수정 시각 오인),
  메타데이터 없이 본문 문자열에서만 읽었는데 API 시각보다 2일 이상 이른 값(사이드바의 다른 기사 날짜 오인).
- 날짜만 있고 시간이 없는 값은 시각으로 추정하지 않습니다. 화면에 `(검색API 기준)` 표시가 있으면 원문에서 시각을 확인하지 못한 기사입니다.

### 기사 선별 / 동명이인
- 1차 선별(제목·요약): 증권·주가·종목, 연예·스포츠, 홍보·제품 출시, 단순 MOU, 수상, 행사 일정, 반도체·AI 중심, 의료 치료 중심,
  정쟁 중심, 사칭·피싱 기사 등을 원문 요청 전에 제외합니다.
- 최종 선별(본문 포함): 제목에 원자력·KINS·원안위·공공기관 핵심어가 있거나, 본문 앞부분과 전체에서 반복적으로 다뤄질 때만 포함합니다.
  키워드가 부수적으로 한두 번 언급된 기사는 제외합니다. AI·데이터센터 기사라도 원전·SMR이 핵심이면 포함합니다.
- 동명이인(임승철·최원호·양이원영·이정윤·한병섭·이헌석·석광훈): 소속기관명(예: `원자력안전연구소`)이 있거나,
  이름 주변에 직함 + 분야 단어가 함께 있을 때만 인정합니다. 동명이인으로 판단되면 해당 인물 키워드만 기사에서 빠지며,
  남는 키워드가 없으면 기사가 제외됩니다. 본문을 확인할 수 없어 판별이 불가하면 제외합니다.
- 원문 접근에 실패하면 본문을 만들지 않고 `본문 확인 불가`로 표시합니다.
- 제외된 기사와 사유는 **제외 기사(검토용)** 탭에서 확인할 수 있습니다(디버그 근거 표시 옵션 포함).

## 6. 중복 제거 방식

| 단계 | 기준 | 처리 |
|---|---|---|
| 1 | URL 완전 동일 (원문 URL 정규화, 네이버 기사 ID `oid/aid`) | 하나의 기사로 병합 |
| 2 | 정규화 제목 완전 동일 (HTML 태그·중복 공백·앞뒤 공백만 제거) | 하나의 기사로 병합 |
| 3 | 같은 사건/보도자료의 다른 기사 | 대표 기사 1건 + `같은 사건 유사 보도 n건`으로 묶음 |

- 1·2단계에서 병합해도 **검색된 키워드는 모두 보존**합니다 (예: `원자력, 원전, SMR`).
- 3단계 판단: 단어 내부 문자 bigram 제목 유사도 + 본문 TF-IDF 유사도 + **제목 숫자 불일치 검사**(예: `3호기` vs `4호기`는 다른 사건).
  제목만 비슷하고 본문이 다르면 묶지 않습니다. 애매한 쌍은 LLM이 설정된 경우 LLM에 판단을 맡깁니다.
- 대표 기사는 중요도가 가장 높은 기사이며, 대표와 직접 비교해 묶어 연쇄 병합을 막습니다.
- 주제별 보기에는 대표 기사만, 키워드별 보기에는 해당 키워드로 실제 검색된 기사만 표시합니다
  (`같은 사건 유사 보도는 1건만 표시` 옵션으로 키워드 내 유사 보도 접기/펼치기).

## 7. 분류 방식

6개 주제(순서 고정) 중 **하나에만** 배치합니다.

1. 한국원자력안전기술원(KINS) 2. 원자력안전위원회 3. 국내 원자력&방사선 4. 국외 원자력&방사선 5. 정부&정치권 6. 기타

규칙 기반 우선순위:
- 제목에 KINS/원안위가 있으면 해당 주제 (둘 다 있으면 **먼저 등장한 주체**, 예: `원안위, KINS 심사 결과 토대로 승인` → 원안위)
- 본문에서 KINS·원안위가 반복적으로 주체로 등장하면 해당 주제
- 원자력 핵심어 없이 공기업·공공기관·출연연 중심 → 기타
- 원자력 중심 기사 중 국회·정당·부처·법안·예산 등 국내 정부/정치 주체 → 정부&정치권, 해외 국가·기관·사건 → 국외, 그 외 → 국내
- LLM 판단이 있으면 LLM 주제를 우선 사용(6개 주제로 검증 후 반영)

중요도(`relevance_score`, 화면 비표시): KINS 직접 관련 > 원자력 안전·규제 > 공식 발표 > 사고·고장·정지·허가·점검 >
정책 영향 > 새로운 사실 > 구체성(본문 길이) > 언론사 신뢰도 > 게시 시각(동점 시 최신 우선). 칼럼·정쟁·추측성 표현은 감점합니다.

## 10. 문제 발생 시 확인할 항목

| 증상 | 확인 사항 |
|---|---|
| `네이버 뉴스 API 인증정보가 설정되어 있지 않습니다` | 프로젝트 폴더에 `.env`가 있는지, `NAVER_CLIENT_ID`/`NAVER_CLIENT_SECRET` 값이 있는지 확인 후 앱 재시작 |
| `네이버 API 인증에 실패했습니다` | ID/Secret 오타, 개발자센터 애플리케이션에 **검색** API가 추가되어 있는지 |
| `호출 한도를 초과했습니다` | 일일 25,000회 한도 — 잠시 후 재시도, 검색 기간 축소 |
| `최대 조회 한도(1,000건)에 도달` 알림 | 해당 키워드 기사가 매우 많음 — 검색 기간을 나누어 실행 |
| 검색이 오래 걸림 | `고급 옵션`에서 원문 확인을 끄면 빠르지만 정확도 저하. `.env`의 `ARTICLE_FETCH_WORKERS` 조정 |
| `본문 확인 불가`가 많음 | 사내 프록시/방화벽이 언론사 사이트를 차단하는지 확인 (네이버 뉴스 페이지로 자동 보완 시도) |
| `(검색API 기준)` 시각 표시 | 원문·네이버 페이지에서 게시 시각을 확인하지 못해 API `pubDate`를 사용한 기사 |
| LLM 관련 알림 | `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL` 확인 — 실패 시 규칙 기반으로 자동 진행 |
| 기대한 기사가 안 보임 | **제외 기사(검토용)** 탭에서 제외 사유 확인, `판단 근거(디버그) 표시` 체크 |
| Excel 다운로드 오류 | `openpyxl` 설치 여부 확인 (`pip install -r requirements.txt`) |

규칙 조정 위치: 제외/포함 용어는 `src/patterns.py`, 동명이인 기준은 `src/config.py`의 `PERSON_RULES`,
중복 판단 임계값은 `src/deduplication.py`, 중요도 가중치는 `src/ranking.py`.
